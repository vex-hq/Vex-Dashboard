## Nothing changed for you today

This release adds no feature you can use. It is the foundation for one, and we
would rather say that plainly than dress up a migration as a launch.

If you want the short version: **Klio can now tell which *person* a memory came
from.** Until today it only knew which organisation and which tool.

## Why that was a problem

Klio had two identities — your organisation, and an agent id like
`oauth:a3f9b21c/cursor`. Neither is a person.

That agent id looks like one, but it is derived from the first eight characters
of a user id plus the tool name. So you running Claude Code and you running
Cursor were two different agents, and two people could collide on eight
characters. There was no way to ask what *you* know, keep something personal
across your own tools, or give one teammate access to one project.

Every one of those needs a person, and there wasn't one.

## What landed

A `user_id` on every memory, resolved from whichever credential you used — your
OAuth session, or the key you created. It is recorded but not yet acted on:
nothing filters by it, and every recall returns exactly what it returned
yesterday.

Deliberately, identity is **never** taken from the `X-Vex-Agent` header. Your
client sends that header, so anything derived from it could be forged by setting
it. Identity comes only from a credential the server verified.

Also landed: the table that will hold project membership, and a per-user cursor
for the curator.

## Memories now record where they came from

Every memory carries a `provenance` label:

| Label | Meaning |
| --- | --- |
| `EXTRACTED` | You said it, or an agent recorded it deliberately |
| `INFERRED` | Klio's curator deduced it from other memories |
| `AMBIGUOUS` | Uncertain — surfaced for review rather than trusted |

This matters more than it sounds. Klio's curator reads your memories and
synthesises new facts from them, and until now those synthesised facts sat in
recall looking exactly like something you had stated outright. An LLM's
deduction and a direct quote are not the same kind of claim, and a memory layer
that cannot tell you which is which is asking you to trust it more than it has
earned.

We backfilled the existing corpus: **1,874 curator-authored facts are now marked
`INFERRED`**, and 38,286 directly-recorded memories are `EXTRACTED`.

## One real bug closed

The `scope` column had no constraint on it. A typo — `privte` instead of
`private` — created a row that no query would ever return: invisible in the
dashboard, unreachable by recall, undeletable through the UI, and still counted
against your quota.

There is now a constraint. A bad scope fails loudly at write time instead of
silently swallowing the memory.

## What comes next

Per-person private memory, where ambient capture from your editor stays yours
until you deliberately share it. Project-scoped memory with real access control.
A dashboard that shows all three.

One commitment worth stating now, before any of it ships: **private will mean
private.** Not private-unless-an-admin-looks. There will be no admin override
and no break-glass path, because a private scope an administrator can read is
not private, and we would rather not build the feature than ship it under a name
that isn't true.

Until that lands, treat everything you write as readable by your organisation —
today's `agent` scope keeps notes out of other agents' recall, but it resolves
against a header your client controls and is not a privacy boundary.
