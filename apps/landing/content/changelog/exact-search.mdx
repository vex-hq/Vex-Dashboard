## Paste the identifier

Recall used to match on meaning alone. That works when you ask a question the
way you would ask a colleague, and it works badly when what you want is a
specific string: `KLIO_METRICS_TOKEN`, `pool_pre_ping`, a commit hash, the exact
text of an error.

Rare strings are precisely where meaning-based search is weakest. The token
carries little signal, so memories that are merely *about* the same subject
crowd out the one memory that actually names the thing. In our own tests the
memory containing the literal ranked **sixth of six**, which at a limit of five
meant it was not returned at all.

Recall now runs a second search over the text itself and combines the two. So
this is a good query, not a lazy one:

```json
{ "query": "KLIO_METRICS_TOKEN" }
```

And this still works exactly as before:

```json
{ "query": "how do we handle auth errors in the API?" }
```

## Nothing you already rely on moved

The two searches are combined by rank rather than by score. That detail is worth
one sentence because it is what makes the change safe: when the text search
matches nothing, the results are **identical** to what you would have got
yesterday. A question phrased as a question, a query of common words, a search
in a workspace with no matching text — all of them land on the old behaviour
exactly, not approximately.

Scope, projects and spaces are untouched. The text search runs under the same
visibility rules as everything else, so it can only ever match memories you
could already read.

## How an identifier is matched

An identifier is matched as its parts, in order. `pool_pre_ping` finds text
containing `pool pre ping` adjacent and in that sequence. A memory that uses all
three words scattered through a sentence does not match, which is what keeps the
results tight.

> Word endings are handled for ordinary prose, so a search for `decisions` still
> finds a memory that wrote `decision`.

## Also in this release

`recall`'s own description advertised only `org` and `agent` scopes. `private`
has worked since private memory shipped, but an agent reading the tool
description had no way to find out. It is listed now.

## What you need to do

Nothing. There is no migration and no configuration change. Existing queries
behave the same; new ones can be more literal.
